How this lab works

Every visible movement comes from the simulator loop. The dashboard does not send commands to a vehicle.

01 / OPERATE

Run a maneuver

  1. Choose one of the six perpendicular, parallel or angled forward/reverse scenarios.
  2. Keep the seed to reproduce a scene, then set Dynamic actors from 0–6 to introduce moving mock vehicles or pedestrians.
  3. Select Reset scenario to generate a new scene and Hybrid A* plan. Use Single step to advance once, or Run loop / Pause loop to execute supervised cycles.
  4. Watch the path, gear, clearance, time-to-collision, event log and supervisor state. BRAKE is a safety decision; it is not a failed UI state.

02 / ARCHITECTURE

From scene to control

Mock world creates a seeded parking scene and synthetic RGB/depth/LiDAR-style proposals. NumPy perception classifies slots and obstacles. Hybrid A* searches kinematic forward/reverse primitives with collision checking. Path tracking follows each gear segment with planned-curvature feedforward plus lateral/heading feedback on a rear-axle bicycle model, stopping at every cusp. Dynamic safety predicts actor motion, then allows progress, replans around a hazard or holds a safe stop.

The public dashboard reports the current decision and event history; it does not hide planner or safety failures.

04 / SCOPE & LIMITATIONS

What this demo is—and is not

This is a research and simulation prototype running a synthetic mock-CARLA backend. It is not connected to CARLA, ROS 2, cameras, LiDAR, CAN, steering, brakes or a vehicle. The compact NumPy MLP is a synthetic-data baseline, not a camera-trained production model; the planner, controller and safety monitor are not certified for road use.

Visitors share one in-memory demo session. Reset changes that shared scene, no run history is saved, and process replacement or idle wake can reset state. Real-system integration needs real sensor adapters, validated perception, vehicle-specific dynamics, independent safety engineering and hardware-in-the-loop validation.
