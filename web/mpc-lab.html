What to change for real-time MPC

The selector compares finite differences with CasADi automatic Jacobians supplied to the same SciPy SLSQP solver. acados and OSQP remain candidates, not selectable implementations.

1 / RETAIN THE BASELINE

Profile and reduce callback work

  • The toggle above compares a shifted previous feasible solution with the geometric Pure Pursuit seed; it remains only an initial guess, not a relaxed constraint.
  • Precompute obstacle polygons/axes and path references; profile finite-difference objective and constraint evaluations.
  • Supply analytic or automatic-differentiation Jacobians; then validate derivatives at polygon feature changes.
  • Reduce the horizon only when collision, goal-capture and disturbance tests still pass.

2 / PRIMARY REAL-TIME CANDIDATE

CasADi + acados SQP-RTI

CasADi can provide sparse algorithmic derivatives for a structured bicycle-model OCP. acados supports SQP real-time iterations split into preparation and feedback phases, designed to reduce control delay. Generate and benchmark the solver for the target CPU; do not assume a deadline from library choice alone.

CasADi documentation →acados RTI features →

3 / CONVEXIFIED ALTERNATIVE

OSQP for sequential QPs

OSQP is a candidate for a warm-started convex QP after local linearization/convexification of vehicle dynamics and obstacle-clearance constraints. It is not a drop-in solver for the current nonlinear polygon-constrained problem. Keep an independent exact-footprint safety check and reject infeasible commands.

OSQP MPC example →
Real-car boundary: the project’s architecture calls for 20–50 Hz control (20–50 ms periods). Passing the 180 ms simulation-step line is not enough. Before any vehicle integration, require target-hardware p99/worst-case deadline evidence, a watchdog and independent safe-stop path, swept-volume or continuous-time collision validation, vehicle-specific system identification, and hardware-in-the-loop and closed-course validation.
